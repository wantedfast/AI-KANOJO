## v1.3 紧凑流光胶囊增补（优先级最高）

- 控制条宽度调整为 `min(520px, calc(100vw - 28px))`，替代此前 1180px 的超宽规范。
- 保持双层低矮玻璃结构、三个纯图标入口、Codex 紧凑状态块与右侧辅助按钮。
- 胶囊上下边缘使用低亮度蓝紫双向流光，运动逻辑参考 React Bits Star Border；禁止使用高噪声 Canvas 电弧、大片霓虹晕染或快速闪烁。
- 尊重系统“减少动态效果”设置；启用后停止装饰性流光。
- Electron 必须采用单实例运行。再次启动时仅唤醒并聚焦现有窗口，不允许产生两个透明窗口和人物重叠。
- 整块胶囊除按钮、输入框等真实控件外均为原生拖动区域；不得只保留顶部细条。拖动验收必须使用 Windows 原生鼠标输入，并验证松手保存与重启恢复。
- 原生移动期间暂停透明区域穿透切换，最后一次移动事件结束 320ms 后保存最终坐标，避免拖动被中断或回弹。
- 拖动采用渲染层按下/松手加主进程全局光标轮询，不依赖 Windows 对透明无边框窗口的原生标题栏拖动。纵向边界以可见胶囊为准，允许透明画布顶部越出工作区，因此 `y=0` 时仍可继续向上移动胶囊。
- 右侧提供“缩小悬浮窗”按钮；缩小后显示 112×44px 小胶囊、8-bit 人物、状态灯与展开按钮。
- 该增补覆盖本文后续仍出现的超宽控制条、无持续装饰性流光等旧规范。

## Problem Statement

当前悬浮控件虽然具备四个功能入口，但形态偏短、偏厚、圆角过大，更像游戏 HUD 或独立胶囊组件，没有复现 Gallery 02 中接近 macOS 菜单栏的超长、低矮、扁平玻璃条。信息被纵向堆叠，彩色发光较多，角色、状态与控制栏之间的关系也不够自然。

用户需要一个长期停留在桌面上、不会抢夺注意力的语音入口：平时只看到 8-bit 罗照月和一条克制的玻璃状态栏；需要时可以快速开始对话、查看女友与 Codex 状态，并进入唱歌或换装功能。悬浮窗必须真的可拖动，同时透明空白区域不能长期阻挡后方桌面。

## Solution

### 产品方案

将常驻界面改为 Gallery 02 风格的“桌面玻璃控制条”：使用超长、低矮、扁平的圆角矩形，而不是短而厚的体育场形胶囊。8-bit 罗照月停靠在控制条上沿；底部主控制层由女友状态、唱歌、换装三个纯图标入口和一个 Codex 状态胶囊组成。语音会话的字幕、暂停与结束操作作为紧凑辅助按钮存在，不扩张主控制条。

产品继续以语音为主，不在常驻界面放置聊天输入框、长文本、日志、进度详情或任务列表。DeepSeek、Scribe 与 Eleven v3 的业务接口保持独立，视觉重构不改变服务协议。

### 视觉风格提炼

Gallery 02 的视觉语言定义如下：

- **形态**：超长、低矮、接近桌面菜单栏比例；不是悬浮卡片，不是大圆角胶囊，不是游戏 HUD。
- **轮廓**：圆角矩形，圆角约 14–18 px；高度明显小于宽度，整体宽高比目标为 8:1–11:1。
- **结构**：上下两条细长玻璃层叠放。上层更薄，以拖动和全局状态为主；下层承载四个功能区和辅助操作。
- **材质**：冷灰蓝透明玻璃，背景内容隐约透出；1 px 低对比描边、顶部轻微内高光、极弱阴影，不使用大范围霓虹光晕。
- **配色**：主体采用蓝黑、石墨灰和雾白；默认状态低饱和，只有正在运行、成功、警告和错误状态使用系统色。
- **排版**：Apple 系统字体栈；主信息 13–15 px、说明 10–12 px；中等字重，避免全大写标题堆叠。
- **图标**：三个主功能使用约 22 px 的单色线性图标和 44–46 px 点击热区；不用 emoji、拟物图标或装饰性图案。
- **分隔**：三个图标之间只使用留白，不使用竖线、圆点或独立卡片。
- **动效**：150–300 ms 系统级缓动；仅状态点、音量波形和必要反馈运动；禁止呼吸式大光晕和持续漂浮。
- **角色关系**：角色坐、躺或停靠在上沿，身体可以越过两层之间的边界，但不得遮挡文案或操作按钮。

### 胶囊与布局规范

这里的“胶囊”指扁平的桌面控制条，不指圆角等于高度一半的体育场形按钮。

| 项目 | 规格 |
|---|---|
| 控制条宽度 | `min(1180px, calc(100vw - 48px))`，在 Electron 窗口内保留 24px 侧边距 |
| 总高度 | 96–116 px，不含角色超出部分 |
| 上层高度 | 32–40 px |
| 下层高度 | 58–72 px |
| 外圆角 | 14–18 px |
| 内边距 | 水平 20–28 px，垂直 8–12 px |
| 描边 | 1 px，白色 12%–20% 透明度 |
| 背景 | 冷灰蓝玻璃，约 58%–76% 不透明度 |
| 模糊 | 浏览器预览 24–36 px；Electron 采用不会产生色带的等效材质 |
| 阴影 | 单层柔和暗影，禁止明显外发光 |
| 角色锚点 | 控制条水平中心附近；横躺图贴上沿，坐姿图使用各自的臀部/支撑手接触锚点 |

#### 上层：全局与拖动层

- 大部分区域作为明确的窗口拖动面。
- 右侧只保留必要的轻量全局信息，例如连接状态和时间；不复制无功能的 macOS Wi‑Fi、搜索、控制中心图标。
- 不放置大标题、品牌口号、聊天内容或常驻按钮组。
- 角色可以穿过上层，但角色可点击区域与拖动区域必须互不冲突。

#### 下层：三图标与 Codex 控制层

1. **女友状态图标**
   - 使用霓虹紫线性图标表达当前状态；错误时临时切换为珊瑚红。
   - 休眠时点击开始语音会话；会话中点击按现有状态机执行暂停、继续或打断。
   - 常驻界面不显示标题或说明；状态名称通过可访问标签和悬停提示提供。

2. **给我唱首歌**
   - 使用霓虹青音乐图标，不显示常驻文字。
   - 保留可点击入口。
   - 当前点击后显示“唱歌功能准备中”，不得播放假音频或伪造唱歌状态。

3. **换装**
   - 使用霓虹粉服装图标，不显示常驻文字。
   - 保留可点击入口。
   - 当前点击后显示“换装功能准备中”，暂不打开选择器。

4. **Codex 状态胶囊**
   - 采用绿色状态点、`Codex` 标签、`Ready / Generating…` 状态文字和五段蓝色电平条。
   - Ready 时电平条静止低亮；Working 时显示 Generating 并让蓝色电平条依次运动。
   - 当前是接口预留，不展示任务详情、日志、进度百分比或虚假执行结果。

#### 会话辅助操作

- 字幕、暂停/继续和结束对话放在控制条右端的紧凑区域。
- 休眠时隐藏或降至不可交互，不占用四个主功能区。
- 字幕默认关闭；开启后只显示当前一句，不形成聊天记录面板。
- 设置继续从系统托盘进入，不占用常驻控制条。

#### 角色呈现

- 休眠时使用默认 8-bit 睡眠图，躺在控制条上沿。
- Listening、Thinking、Speaking、Completed 与 Error 自动切换现有运行时资产及复用规则。
- 唤醒后保留默认 Modern JK 2D 立绘，位于控制条左侧并轻微叠压；不得迫使控制条变高。
- 角色、控制条、状态点和立绘作为同一个桌面组件整体移动。

## User Stories

1. 作为用户，我希望罗照月和控制条长期停留在桌面上，以便随时开始语音对话。
2. 作为用户，我希望界面像 macOS 菜单栏一样低矮克制，以免遮挡正在使用的应用。
3. 作为用户，我希望控制条足够长且信息横向排列，以便快速扫读状态而不是阅读卡片。
4. 作为用户，我希望休眠时只看到睡眠角色和最少信息，以便桌面保持安静。
5. 作为用户，我希望点击休眠角色或女友状态区即可开始对话，以便入口自然一致。
6. 作为用户，我希望通过图标、短状态和颜色辨认 Listening、Thinking、Speaking、Completed 与 Error。
7. 作为用户，我希望 Codex 与女友状态分开显示，以免把后台工作与对话状态混淆。
8. 作为用户，我希望 Codex 未接入时诚实显示 Standby，而不是伪造进度。
9. 作为用户，我希望唱歌和换装入口可被发现，同时明确知道它们尚未完成。
10. 作为用户，我希望字幕默认隐藏，以便语音仍是核心体验。
11. 作为用户，我希望需要时能快速暂停、继续或结束会话。
12. 作为用户，我希望能抓住上层玻璃条拖动整个组件，并在重启后恢复位置。
13. 作为用户，我希望透明空白区域可点击穿透，以免悬浮窗阻挡桌面。
14. 作为用户，我希望锁定位置后按钮仍然可用，但窗口不会误移动。
15. 作为使用高分屏或多显示器的用户，我希望控制条不会被裁切或移出可见区域。
16. 作为开启“减少动态效果”的用户，我希望非必要动画自动停止。
17. 作为视觉敏感用户，我希望颜色只表达状态，不出现持续霓虹和装饰性发光。
18. 作为语音用户，我希望插话时旧回复在 200 ms 目标内停止并回到监听状态。

## Implementation Decisions

### 桌面窗口

- 使用透明、无边框、置顶、隐藏普通任务栏入口的 Electron 窗口。
- 窗口尺寸必须给控制条留出至少 200 px 的水平移动余量；不得恢复会吞满工作区的历史宽高。
- 渲染层上报真实按钮、角色、控制条、拖动层与设置面板命中矩形；主进程根据全局鼠标坐标控制透明区域穿透。
- 上层拖动面通过受限 preload IPC 将屏幕坐标传给主进程；拖动期间暂停透明穿透切换，避免 Windows 取消拖动并回弹。
- 拖动结束时一次性保存最终窗口坐标，普通移动事件仅作防抖兜底；重启后恢复最终坐标并校正到可见工作区。
- 托盘提供显示/隐藏、锁定、设置、停止语音和退出。

### 状态与功能

- 继续复用现有女友状态机：`idle → listening → thinking → speaking → completed → idle`，任何阶段可进入 `error`。
- Codex 只保留 `standby / working` 视觉状态和未来接口边界，本版本不接入电脑任务执行。
- 唱歌和换装保留独立点击处理函数，本版本不增加后端 IPC。
- DeepSeek、Scribe、Eleven v3 的协议、凭据保存与取消机制不因视觉重构改变。

### 资产

- 视觉基准固定为 `assets/ui-concepts/02-desktop-pet.png`。
- 女主身份基准固定为 `assets/character/luo-zhaoyue/source/luo-zhaoyue-lookdev-v005.png`。
- 运行时使用 `public/avatar/8bit/manifest.json` 及四张正式状态 PNG。
- `speaking` 复用 Listening 资产，`error` 复用 Thinking 资产，直到补齐独立美术。
- 默认 2D 立绘使用 Modern JK；不引入 Live2D。

### 语音、数据与安全

- DeepSeek 负责流式对话文本，Scribe 负责实时识别，Eleven v3 负责语音合成。
- 只有 Scribe committed transcript 才提交，并按结果 ID 去重。
- ElevenLabs 正式 TTS 模型 ID 固定为 `eleven_v3`。
- 最近会话、普通设置和窗口位置本地持久化；麦克风原始音频默认不落盘。
- DeepSeek 与 ElevenLabs Key 使用操作系统保护能力保存；渲染进程、日志、测试和仓库不得出现明文凭据。

## Testing Decisions

- 测试只验证用户可观察行为和真实窗口结果，不依赖 CSS 类名数量或内部计时器细节。
- 组件层验证六种女友状态、Codex 两种状态、唱歌与换装反馈、字幕、暂停和结束会话。
- Electron 层验证透明置顶窗口、主进程命中区域、鼠标穿透、位置锁定、托盘入口和窗口位置恢复。
- 使用 Windows 原生鼠标输入从上层拖动面拖动至少 200 px，并验证操作系统窗口坐标变化；程序调用 `setPosition` 不能替代该测试。
- 在 1280 × 720、1920 × 1080 和 150% 缩放下检查控制条无裁切，角色不遮挡状态或按钮。
- Design QA 必须把 Gallery 02 与实现截图放入同一个对照画布，检查宽高比、圆角、层高、描边、透明度、排版、分隔与角色锚点。
- 视觉验收的 P0–P2 问题全部关闭后运行 `npm run verify`；演示模式必须完成完整状态流。
- 真实 Scribe 与 Eleven v3 验收依赖合法凭据和麦克风环境，自动测试不能替代真实服务测试。

## Out of Scope

- 复制 macOS 的 Apple 标志、File/Edit/View 菜单、Wi‑Fi、搜索、日期或系统控制中心。
- Codex 真实任务执行、日志、进度、电脑控制或远程控制。
- 唱歌和换装的真实业务能力。
- Live2D、3D、全身行走、舞蹈或复杂逐帧动画。
- 独立 Speaking、Error 运行时美术资产。
- 常驻文字聊天框、聊天历史面板和任务详情面板。
- 未经授权的真人声音克隆或公网开放本地服务。
