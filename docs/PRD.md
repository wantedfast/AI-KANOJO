## v1.9 外挂式文字聊天与简短语音对话

> 版本：1.9
>
> 日期：2026-08-01
>
> 状态：前端产品设计已确认，等待前端实现
>
> 视觉基准：已选定的“侧置亲密聊天”方向及无 2D 立绘语音浮层
>
> 最高约束：现有胶囊设计完全不变；本需求只包含前端

### Problem Statement

当前麦克风入口与粉色聊天入口复用同一条语音会话逻辑，点击后只在原胶囊上切换状态。应用没有独立的文字聊天界面，因此用户无法区分“查看并输入文字消息”和“开始一段简短语音对话”，也容易把正常的原地状态切换理解为按钮没有响应。

现有胶囊已经完成视觉定稿和桌面行为验证，不应为新增聊天能力重新排版或改变尺寸。新增体验需要在不触碰胶囊本体的前提下，让两个入口的用途、反馈和退出方式一眼可辨。

### Solution

保留现有胶囊的全部视觉、结构与桌面行为，在胶囊外新增两个互斥的外挂式会话表面：

1. **文字聊天面板**：点击现有粉色聊天入口，在胶囊上方打开轻量竖向聊天面板，显示由外部数据契约提供的最近消息、文字输入框和发送操作。
2. **简短语音浮层**：点击现有紫色麦克风入口，只打开紧凑语音状态浮层，不显示完整历史。浮层最多显示当前用户转写、罗照月当前回复、单一状态和暂停/结束操作。一次回答播放完成后自动继续监听。

两个表面都在现有前端透明画布内锚定胶囊，但不改变胶囊的尺寸、布局、颜色、图标顺序、8-bit 角色槽位、Codex 状态、交通灯、拖动命中区或缩小态。大尺寸 2D Modern JK 立绘从所有状态中移除，160px 8-bit 罗照月成为唯一角色呈现。本需求不实现或修改任何后端服务、Provider、密钥、IPC、音频传输或持久化能力。

### Product And Interaction Requirements

#### 胶囊冻结边界

- 现有胶囊按当前实现逐像素保留，不增加、删除、移动或重绘任何胶囊内元素。
- 不改变展开态和缩小态尺寸、圆角、玻璃材质、品牌边缘光、图标命中区、8-bit 锚点、Codex 块或窗口控制。
- 不改变拖动、透明区域穿透、位置持久化、单实例、缩小和退出行为。
- 新面板必须在现有透明渲染画布内出现；不得调整 Electron 窗口大小或位置，胶囊自身不得缩放、偏移或发生布局重排。

#### 文字聊天面板

- 点击粉色聊天入口时打开；再次点击、点击关闭、按 Escape 或结束聊天时关闭。
- 面板锚定在胶囊上方，采用约 360px 宽的竖向深石墨蓝玻璃表面，不成为全屏或常规 IM 主窗口。
- 顶部显示“罗照月”、当前在线/回复状态以及关闭操作，不显示大头像或 2D 立绘。
- 主区域显示最近 24 条用户/罗照月消息；打开时滚动到最新消息。
- 用户消息与罗照月消息使用方向、对齐和低亮色差区分，不使用高强度聊天气泡霓虹。
- 底部提供单行或自动增高的文字输入框、发送按钮和明确的输入焦点状态。
- Enter 发送，Shift+Enter 换行；空消息、全空格消息和回复生成期间的重复提交不得发送。
- 发送后立即显示用户消息，并进入 `thinking`；外部聊天数据流到达时逐步更新当前罗照月消息。
- 外部播放状态表明回复正在朗读时，对应消息显示轻量播放反馈；前端不发起语音合成。
- 关闭面板不删除消息，重新打开恢复最近聊天历史。
- 文字聊天和简短语音浮层互斥；打开文字聊天时停止语音自动监听并关闭语音浮层。

#### 简短语音浮层

- 点击紫色麦克风入口时打开；不打开文字聊天历史。
- 浮层锚定在麦克风上方，目标约 360×150px；不覆盖 8-bit 角色、Codex 或窗口控制。
- 只使用一个会随状态变化的位置显示 `正在听… / 思考中… / 正在说… / 已暂停 / 出错了`，不得同时堆叠多个状态卡片。
- 最多显示一条当前用户实时转写和一条罗照月当前回复；新一轮开始后替换旧内容，不形成可滚动历史。
- 提供紧凑的暂停/继续与结束操作；不把这些控制塞回胶囊。
- 状态流固定为 `listening → thinking → speaking → completed → listening`。
- 外部语音事件提交完整转写后，前端进入 `thinking`；收到回复完成及播放就绪事件后进入 `speaking`。
- 收到播放结束并恢复监听事件后，前端回到 `listening`，并显示“回复后继续倾听”的低对比提示。
- 暂停、结束、离线、权限拒绝、模型错误或播放错误时不得自动重新监听。
- 结束后浮层收起，胶囊回到既有空闲状态。
- 打开语音浮层时关闭文字聊天面板，但保留双方消息作为最近记忆。

#### 角色与状态反馈

- 移除所有状态下的大尺寸 2D Modern JK 立绘及其占位区域。
- 仅使用现有 160px 8-bit 罗照月状态资产表达 idle、listening、thinking、speaking、completed 和 error。
- 状态切换只改变既有 8-bit 资源和动画，不改变其长边尺度或胶囊锚点。
- 外挂面板不得重复显示人物头像、圆形照片或缩略立绘。

#### 前端数据契约

- 后端由用户的其他方案负责；前端只消费注入的消息、语音阶段、当前转写、当前回复、播放状态、配置状态和可见错误。
- 文字与语音入口在前端展示同一份外部消息历史，因此切换入口时保持上下文连续。
- 消息至少包含稳定 ID、`user / assistant` 角色、文本、创建时间和 `pending / streaming / complete / error` 状态。
- 语音阶段只接受 `idle / listening / thinking / speaking / completed / paused / error`。
- 前端只发出 `sendText / startVoice / pauseVoice / resumeVoice / endVoice / closeSurface` 用户意图，不直接请求模型、识别或合成服务。
- 前端不得包含模型 ID、Provider URL、API 密钥、Voice ID、加密逻辑或降级规则。
- 前端预览和组件测试使用可控假数据适配器；假数据不得进入正式后端逻辑或伪装成真实会话。

#### 配置、错误与可访问性

- 外部契约报告未配置时，两个入口显示后端提供的可读原因；前端不负责配置密钥或 Voice ID。
- 外部契约报告麦克风不可用时，语音浮层显示可操作错误；文字聊天仍可正常使用。
- 外部契约报告网络、服务或播放错误时，当前外挂表面必须可见展示；不得静默回到 idle。
- 所有可交互元素支持键盘焦点、清晰的可访问名称和至少 32px 的有效命中区域。
- 尊重系统减少动态效果设置；波形和状态动画在该设置下改为静态反馈。

### User Stories

1. 作为用户，我希望现有胶囊保持原样，以便新功能不会破坏已经熟悉的桌面伴侣外观。
2. 作为用户，我希望点击粉色聊天入口能看到文字聊天面板，以便确认按钮已经响应。
3. 作为用户，我希望点击麦克风只进入简短语音对话，以便不用面对完整聊天记录。
4. 作为文字聊天用户，我希望输入并发送消息，以便在不方便说话时与罗照月交流。
5. 作为文字聊天用户，我希望看到流式回复，以便感知罗照月正在回应。
6. 作为文字聊天用户，我希望看到回复的朗读状态，以便知道罗照月何时正在说话。
7. 作为文字聊天用户，我希望关闭并重新打开面板后仍能看到最近消息，以便继续先前话题。
8. 作为语音用户，我希望只看到当前一问一答，以便语音浮层保持简洁。
9. 作为语音用户，我希望明确看到正在听、思考和说话状态，以便知道系统当前在做什么。
10. 作为语音用户，我希望罗照月说完后自动继续监听，以便自然地连续聊天。
11. 作为语音用户，我希望随时暂停或结束，以便掌控麦克风和会话。
12. 作为用户，我希望语音和文字入口共享最近记忆，以便切换方式时无需重复上下文。
13. 作为用户，我希望文字面板和语音浮层不会同时遮挡桌面，以便界面始终克制。
14. 作为用户，我希望外部面板随胶囊一起移动，以便桌面伴侣保持一个整体。
15. 作为用户，我希望关闭外挂面板后胶囊位置不变，以便不会打乱桌面布局。
16. 作为用户，我希望只看到 8-bit 罗照月，以便人物表达统一且不重复。
17. 作为用户，我希望播放期间界面不显示正在监听，以便不会误解当前状态。
18. 作为用户，我希望外部服务未配置时看到明确提示，以便不会误以为按钮失效。
19. 作为用户，我希望外部服务不可用时看到真实错误，以便知道当前会话没有成功。
20. 作为键盘用户，我希望可以用 Enter 发送、Escape 关闭并访问所有控制，以便不依赖鼠标。
21. 作为减少动态效果的用户，我希望波形和动画变得克制，以便舒适使用。
22. 作为桌面用户，我希望缩小、拖动、穿透和重启恢复继续正常，以便聊天功能不破坏原有桌面行为。

### Implementation Decisions

- 在现有应用壳中新增 `text-chat` 与 `voice-popover` 两种互斥表面状态，不新增路由或全屏窗口。
- 新增纯前端会话适配器边界，将外部状态映射为 UI 所需的消息、阶段、转写、回复、播放和错误数据。
- 文字输入和语音控制只调用适配器提供的意图回调，不直接调用 IPC、网络、Provider 或浏览器麦克风 API。
- 面板渲染在现有透明画布中，使用定位和层级管理避开胶囊、8-bit、Codex 与窗口控制，不修改主进程窗口范围。
- 语音浮层展示临时当前轮数据，文字面板展示外部提供的消息历史；前端不负责保存或加密历史。
- 切换表面时由前端忽略先前表面的迟到 UI 事件，并向适配器发出关闭意图；实际请求与音频取消由外部后端负责。
- 大尺寸 2D 立绘从渲染树和命中区域中移除，避免留下透明点击阻挡或窗口尺寸空洞。
- 实现文件限定在前端渲染层、样式、前端状态适配和前端测试；不得修改 Electron 主进程、preload、Provider、凭证导入或存储模块。

### Testing Decisions

- 测试以用户可见行为为主，不断言内部函数调用顺序；优先使用现有组件层与 Electron smoke 层测试缝隙。
- 胶囊回归测试对比新增前后的尺寸、关键元素坐标、图标顺序、8-bit 槽位、Codex 和窗口控制，要求完全不变。
- 文字聊天组件测试覆盖打开/关闭、输入发送、流式回复、历史恢复、Enter/Shift+Enter、重复提交和可见错误。
- 语音组件测试覆盖一问一答呈现、状态单点切换、TTS 期间不监听、播放结束恢复监听、暂停/结束/错误不重启。
- 互斥测试覆盖从文字切到语音、从语音切到文字以及快速重复点击，确保旧表面的迟到事件不会重新打开或覆盖当前 UI。
- 适配器契约测试使用假数据覆盖消息流、阶段流、错误、未配置和播放状态，不调用任何真实外部服务。
- 现有 Electron smoke 仅作为胶囊回归检查，覆盖胶囊屏幕坐标不变、拖动命中、透明穿透、关闭收起、位置恢复和缩小态；不新增主进程行为。
- 视觉验收覆盖无大尺寸 2D 立绘、仅有一个 8-bit 角色、面板不覆盖角色/Codex/窗口控制，以及减少动态效果状态。
- 使用前端假适配器完成一次文字“输入—流式回复—朗读状态”和一次语音“监听—思考—说话—继续监听”验收；真实后端联调不属于本 PRD。

### Out of Scope

- 改动现有胶囊的任何视觉、尺寸、布局、控件或动画。
- 全屏聊天应用、独立聊天主窗口、侧边栏、会话列表、多角色或多联系人。
- 长期云端记忆、跨设备同步、搜索、导出、附件、图片、文件和富文本消息。
- Live2D、2D Modern JK 立绘、表情系统或新增角色资产。
- 唱歌、换装和 Codex 功能重构。
- 模型切换、旧模型回退、Voice ID 自动选择或多声音管理。
- 回声消除算法、多人语音、电话模式或后台持续监听。
- DeepSeek、ElevenLabs、Scribe 或其他模型与语音服务的选择、请求、流式传输、错误重试和降级。
- API 密钥、Voice ID、safeStorage、设置导入、凭证校验和任何安全存储。
- Electron 主进程、preload、IPC 实现、窗口尺寸调整、音频播放、麦克风采集和历史持久化。
- 真实后端联调与端到端 Provider 验收。

### Further Notes

- 本节只定义下一轮文字聊天与简短语音对话；与其冲突的旧版“无聊天历史面板”和“保留 2D 立绘”要求由本节覆盖。
- 胶囊冻结是验收门槛，不是视觉建议。任何实现若导致胶囊尺寸、位置、内部布局或视觉发生变化，均视为未完成。
- 实现前应以当前 Electron 正式运行态截图记录胶囊基线，完成后用相同屏幕和状态进行像素级比较。
- 后端团队只需按“前端数据契约”提供状态与意图适配；其技术选型和内部行为不受本 PRD 约束。

## v1.8 Apple 审计整改（本地候选版）

- 唤醒后的 2D Modern JK 立绘缩至约 220px，并靠近胶囊左端形成轻微重叠，避免立绘与胶囊成为两个断裂的悬浮岛。
- 8-bit 角色继续位于功能图标与 Codex 之间，保持 160px 长边和既有状态映射。
- Codex 工作状态文案从会截断的 `Generating…` 收敛为 `Working`；保留状态点与五段电平，但降低边框、阴影和光晕强度。
- 胶囊主体改为更中性的深石墨蓝玻璃，紫青品牌光只保留为低亮侧缘和缓慢流光；常态霓虹显著降低。
- 缩小态宽度由 112px 调整为 160px，与固定 160px 角色长边建立一致比例；高度继续为 44px。
- 窗口控制调整为胶囊最右侧的竖向紧凑双点：红色关闭在上、黄色缩小在下。可见圆点为 12px、间距约 8px，使用 32×20px 命中区域；悬停显示 `× / −` 和功能提示。
- 展开态胶囊由 520px 收紧为 500px；Codex 状态块额外左移 4px，减少睡眠态和工作态中央的松散留白，同时必须继续通过 8-bit 与 Codex 无重叠验证。
- 2D Modern JK 只在非 `idle` 的唤醒会话状态出现；初始休眠和会话结束回到 `idle` 时必须立即隐藏，只保留 8-bit 睡姿角色。

## Problem Statement

当前悬浮控件虽然具备四个功能入口，但形态偏短、偏厚、圆角过大，更像游戏 HUD 或独立胶囊组件，没有复现 Gallery 02 中接近 macOS 菜单栏的超长、低矮、扁平玻璃条。信息被纵向堆叠，彩色发光较多，角色、状态与控制栏之间的关系也不够自然。

用户需要一个长期停留在桌面上、不会抢夺注意力的语音入口：平时只看到 8-bit 罗照月和一条克制的玻璃状态栏；需要时可以快速开始对话、查看女友与 Codex 状态，并进入唱歌或换装功能。悬浮窗必须真的可拖动，同时透明空白区域不能长期阻挡后方桌面。

## Solution

### 产品方案

将常驻界面改为 Gallery 02 风格的“桌面玻璃控制条”：使用超长、低矮、扁平的圆角矩形，而不是短而厚的体育场形胶囊。8-bit 罗照月停靠在控制条上沿；底部主控制层由女友状态、唱歌、换装三个纯图标入口和一个 Codex 状态胶囊组成。语音会话的字幕、暂停与结束操作作为紧凑辅助按钮存在，不扩张主控制条。

产品继续以语音为主，不在常驻界面放置聊天输入框、长文本、日志、进度详情或任务列表。DeepSeek、Scribe 与 Eleven v3 的业务接口保持独立，视觉重构不改变服务协议。

### 视觉风格提炼

Gallery 02 的视觉语言定义如下：

- **形态**：超长、低矮、接近桌面菜单栏比例；不是悬浮卡片，不是大圆角胶囊，不是游戏 HUD。
- **轮廓**：圆角矩形，圆角约 14–18 px；高度明显小于宽度，整体宽高比目标为 8:1–11:1。
- **结构**：上下两条细长玻璃层叠放。上层更薄，以拖动和全局状态为主；下层承载四个功能区和辅助操作。
- **材质**：冷灰蓝透明玻璃，背景内容隐约透出；1 px 低对比描边、顶部轻微内高光、极弱阴影，不使用大范围霓虹光晕。
- **配色**：主体采用蓝黑、石墨灰和雾白；默认状态低饱和，只有正在运行、成功、警告和错误状态使用系统色。
- **排版**：Apple 系统字体栈；主信息 13–15 px、说明 10–12 px；中等字重，避免全大写标题堆叠。
- **图标**：三个主功能使用约 22 px 的单色线性图标和 44–46 px 点击热区；不用 emoji、拟物图标或装饰性图案。
- **分隔**：三个图标之间只使用留白，不使用竖线、圆点或独立卡片。
- **动效**：150–300 ms 系统级缓动；仅状态点、音量波形和必要反馈运动；禁止呼吸式大光晕和持续漂浮。
- **角色关系**：角色坐、躺或停靠在上沿，身体可以越过两层之间的边界，但不得遮挡文案或操作按钮。

### 胶囊与布局规范

这里的“胶囊”指扁平的桌面控制条，不指圆角等于高度一半的体育场形按钮。

| 项目 | 规格 |
|---|---|
| 控制条宽度 | `min(1180px, calc(100vw - 48px))`，在 Electron 窗口内保留 24px 侧边距 |
| 总高度 | 96–116 px，不含角色超出部分 |
| 上层高度 | 32–40 px |
| 下层高度 | 58–72 px |
| 外圆角 | 14–18 px |
| 内边距 | 水平 20–28 px，垂直 8–12 px |
| 描边 | 1 px，白色 12%–20% 透明度 |
| 背景 | 冷灰蓝玻璃，约 58%–76% 不透明度 |
| 模糊 | 浏览器预览 24–36 px；Electron 采用不会产生色带的等效材质 |
| 阴影 | 单层柔和暗影，禁止明显外发光 |
| 角色锚点 | 控制条水平中心附近；横躺图贴上沿，坐姿图使用各自的臀部/支撑手接触锚点 |

#### 上层：全局与拖动层

- 大部分区域作为明确的窗口拖动面。
- 右侧只保留必要的轻量全局信息，例如连接状态和时间；不复制无功能的 macOS Wi‑Fi、搜索、控制中心图标。
- 不放置大标题、品牌口号、聊天内容或常驻按钮组。
- 角色可以穿过上层，但角色可点击区域与拖动区域必须互不冲突。

#### 下层：三图标与 Codex 控制层

1. **女友状态图标**
   - 使用霓虹紫线性图标表达当前状态；错误时临时切换为珊瑚红。
   - 休眠时点击开始语音会话；会话中点击按现有状态机执行暂停、继续或打断。
   - 常驻界面不显示标题或说明；状态名称通过可访问标签和悬停提示提供。

2. **给我唱首歌**
   - 使用霓虹青音乐图标，不显示常驻文字。
   - 保留可点击入口。
   - 当前点击后显示“唱歌功能准备中”，不得播放假音频或伪造唱歌状态。

3. **换装**
   - 使用霓虹粉服装图标，不显示常驻文字。
   - 保留可点击入口。
   - 当前点击后显示“换装功能准备中”，暂不打开选择器。

4. **Codex 状态胶囊**
   - 采用绿色状态点、`Codex` 标签、`Ready / Generating…` 状态文字和五段蓝色电平条。
   - Ready 时电平条静止低亮；Working 时显示 Generating 并让蓝色电平条依次运动。
   - 当前是接口预留，不展示任务详情、日志、进度百分比或虚假执行结果。

#### 会话辅助操作

- 字幕、暂停/继续和结束对话放在控制条右端的紧凑区域。
- 休眠时隐藏或降至不可交互，不占用四个主功能区。
- 字幕默认关闭；开启后只显示当前一句，不形成聊天记录面板。
- 设置继续从系统托盘进入，不占用常驻控制条。

#### 角色呈现

- 休眠时使用默认 8-bit 睡眠图，躺在控制条上沿。
- Listening、Thinking、Speaking、Completed 与 Error 自动切换现有运行时资产及复用规则。
- 唤醒后保留默认 Modern JK 2D 立绘，位于控制条左侧并轻微叠压；不得迫使控制条变高。
- 角色、控制条、状态点和立绘作为同一个桌面组件整体移动。

## User Stories

1. 作为用户，我希望罗照月和控制条长期停留在桌面上，以便随时开始语音对话。
2. 作为用户，我希望界面像 macOS 菜单栏一样低矮克制，以免遮挡正在使用的应用。
3. 作为用户，我希望控制条足够长且信息横向排列，以便快速扫读状态而不是阅读卡片。
4. 作为用户，我希望休眠时只看到睡眠角色和最少信息，以便桌面保持安静。
5. 作为用户，我希望点击休眠角色或女友状态区即可开始对话，以便入口自然一致。
6. 作为用户，我希望通过图标、短状态和颜色辨认 Listening、Thinking、Speaking、Completed 与 Error。
7. 作为用户，我希望 Codex 与女友状态分开显示，以免把后台工作与对话状态混淆。
8. 作为用户，我希望 Codex 未接入时诚实显示 Standby，而不是伪造进度。
9. 作为用户，我希望唱歌和换装入口可被发现，同时明确知道它们尚未完成。
10. 作为用户，我希望字幕默认隐藏，以便语音仍是核心体验。
11. 作为用户，我希望需要时能快速暂停、继续或结束会话。
12. 作为用户，我希望能抓住上层玻璃条拖动整个组件，并在重启后恢复位置。
13. 作为用户，我希望透明空白区域可点击穿透，以免悬浮窗阻挡桌面。
14. 作为用户，我希望锁定位置后按钮仍然可用，但窗口不会误移动。
15. 作为使用高分屏或多显示器的用户，我希望控制条不会被裁切或移出可见区域。
16. 作为开启“减少动态效果”的用户，我希望非必要动画自动停止。
17. 作为视觉敏感用户，我希望颜色只表达状态，不出现持续霓虹和装饰性发光。
18. 作为语音用户，我希望插话时旧回复在 200 ms 目标内停止并回到监听状态。

## Implementation Decisions

### 桌面窗口

- 使用透明、无边框、置顶、隐藏普通任务栏入口的 Electron 窗口。
- 窗口尺寸必须给控制条留出至少 200 px 的水平移动余量；不得恢复会吞满工作区的历史宽高。
- 渲染层上报真实按钮、角色、控制条、拖动层与设置面板命中矩形；主进程根据全局鼠标坐标控制透明区域穿透。
- 上层拖动面通过受限 preload IPC 将屏幕坐标传给主进程；拖动期间暂停透明穿透切换，避免 Windows 取消拖动并回弹。
- 拖动结束时一次性保存最终窗口坐标，普通移动事件仅作防抖兜底；重启后恢复最终坐标并校正到可见工作区。
- 托盘提供显示/隐藏、锁定、设置、停止语音和退出。

### 状态与功能

- 继续复用现有女友状态机：`idle → listening → thinking → speaking → completed → idle`，任何阶段可进入 `error`。
- Codex 只保留 `standby / working` 视觉状态和未来接口边界，本版本不接入电脑任务执行。
- 唱歌和换装保留独立点击处理函数，本版本不增加后端 IPC。
- DeepSeek、Scribe、Eleven v3 的协议、凭据保存与取消机制不因视觉重构改变。

### 资产

- 视觉基准固定为 `assets/ui-concepts/02-desktop-pet.png`。
- 女主身份基准固定为 `assets/character/luo-zhaoyue/source/luo-zhaoyue-lookdev-v005.png`。
- 运行时使用 `public/avatar/8bit/manifest.json` 及四张正式状态 PNG。
- `speaking` 复用 Listening 资产，`error` 复用 Thinking 资产，直到补齐独立美术。
- 默认 2D 立绘使用 Modern JK；不引入 Live2D。

### 语音、数据与安全

- DeepSeek 负责流式对话文本，Scribe 负责实时识别，Eleven v3 负责语音合成。
- 只有 Scribe committed transcript 才提交，并按结果 ID 去重。
- ElevenLabs 正式 TTS 模型 ID 固定为 `eleven_v3`。
- 最近会话、普通设置和窗口位置本地持久化；麦克风原始音频默认不落盘。
- DeepSeek 与 ElevenLabs Key 使用操作系统保护能力保存；渲染进程、日志、测试和仓库不得出现明文凭据。

## Testing Decisions

- 测试只验证用户可观察行为和真实窗口结果，不依赖 CSS 类名数量或内部计时器细节。
- 组件层验证六种女友状态、Codex 两种状态、唱歌与换装反馈、字幕、暂停和结束会话。
- Electron 层验证透明置顶窗口、主进程命中区域、鼠标穿透、位置锁定、托盘入口和窗口位置恢复。
- 使用 Windows 原生鼠标输入从上层拖动面拖动至少 200 px，并验证操作系统窗口坐标变化；程序调用 `setPosition` 不能替代该测试。
- 在 1280 × 720、1920 × 1080 和 150% 缩放下检查控制条无裁切，角色不遮挡状态或按钮。
- Design QA 必须把 Gallery 02 与实现截图放入同一个对照画布，检查宽高比、圆角、层高、描边、透明度、排版、分隔与角色锚点。
- 视觉验收的 P0–P2 问题全部关闭后运行 `npm run verify`；演示模式必须完成完整状态流。
- 真实 Scribe 与 Eleven v3 验收依赖合法凭据和麦克风环境，自动测试不能替代真实服务测试。

## Out of Scope

- 复制 macOS 的 Apple 标志、File/Edit/View 菜单、Wi‑Fi、搜索、日期或系统控制中心。
- Codex 真实任务执行、日志、进度、电脑控制或远程控制。
- 唱歌和换装的真实业务能力。
- Live2D、3D、全身行走、舞蹈或复杂逐帧动画。
- 独立 Speaking、Error 运行时美术资产。
- 常驻文字聊天框、聊天历史面板和任务详情面板。
- 未经授权的真人声音克隆或公网开放本地服务。
